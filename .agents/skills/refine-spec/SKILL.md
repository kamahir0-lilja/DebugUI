# 仕様を具体化する

[仕様ワークフロー](../../../docs/contributing/specification-workflow.md)に従う。

- 依頼の目的と範囲、関係する採用済み仕様、必要な知見だけを読む。
- ユーザーの要求/希望/案とAgent Decisionを区別し、操作前の状態→操作→結果、失敗/取消/回復を具体化する。
- 既存仕様を変えるなら変更提案、新規領域なら仕様ひな形を使う。公開API・保存値・テーマ・配布への影響を示す。
- 受け入れ条件からテストとUIケースを追えるようにする。知見のworkaroundをそのまま製品要件にしない。
- 対象範囲で決められる選択は理由付きで解決し、実質的な未決事項だけ残す。

出力は短いDraft / Proposed、根拠と判断、検証方法、残る論点。このpassでは承認せず、書き終えた提案をレビューへ渡す。
