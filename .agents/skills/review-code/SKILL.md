# 実装をレビューする

今回の目的、Git差分、対象の採用済み仕様、テストと実際の操作結果を確認する。

最初に製品の問題を探す。初期化/破棄、ページ履歴・所有権、通知の重複、フォーカス・テーマ・狭い画面、
公開API・リソース解決など変更に関係する箇所を確認する。
次に証拠を確認する。[UI検証ワークフロー](../../../docs/contributing/ui-validation-workflow.md)に対する検証不足、
修正前の画像の流用、未実行環境の成功扱い、古い知見や不要になった回避策の追従漏れを確認する。

出力は対象範囲、要件との対応、具体的なfindings、検証と限界、判定。
仕様違反は不具合、期待結果が決まらない場合は仕様不足として区別し、好みの変更は軽微な提案に留める。
別エージェントは必須ではない。通常の実装では差分の自己レビューとして行える。
