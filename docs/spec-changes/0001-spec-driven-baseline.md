# 0001: 仕様駆動開発の初期整理

Status: Applied

## 目的・根拠

ユーザーからmasterdata / masterdata-legacy2を参考に仕様駆動開発の環境整備、
既存知見の活用、Unity Editor拡張スキルとの関係整理を依頼された。
AGENTS.mdを軽く保つ既存の意向と、実装中の確認・最後のAI画像レビュー・Unity終了確認を維持する。

Agent Decision: 文書の入口、仕様の状態と受け入れ条件、短い活動スキル、構造検査を追加する。
既存の公開説明と検証ケースから主要操作の初期仕様を整理し、コードの細部や過去の回避策すべては契約にしない。
外部リポジトリ固有の製品前提やGit操作の許可は引き継がない。

## 適用先と互換性

- [ライフサイクルとページ](../specs/runtime-and-hosts.md)
- [表示と操作](../specs/presentation-and-controls.md)

製品のコード・公開API・アセット・依存関係・保存値は変更しない。
UI自動撮影・画像比較・外部AI一括ランナーの実装、未実行環境の動作保証は対象外。

## レビュー・採用

提案作成後の別passで、依頼との一致、知見と仕様の区別、テスト/操作への接続、重複、参照先、過度な承認待ちがないことを確認した。

- Blocking: なし。レビュー中に、製品仕様へ混ざっていた検証設定の復元手順を除き、手順書を正本とした。
- 軽微な指摘: 要件へのリンクが見出し名の変更で壊れないよう、ID単独の見出しへ整理した。
- 未決事項: 主要操作の初期基準を採用する範囲ではなし。全API境界・未実行環境の保証は追加していない。
- 採用可否: 可。既存の主要な公開説明と確認ケースを基準として選ぶ判断であり、製品コードや公開操作の変更を含まない。
- Approval mode: Agent-autonomous。根拠は今回の仕様駆動環境整備の依頼と、上記のAgent Decisionおよびレビュー結果。

正本3件へ適用し、状態をApprovedとした。Appliedは仕様整理の反映完了であり、
今回のUnity実行や全機能の検証完了ではない。既存の過去の検証結果を新しい結果として流用せず、Implementedには進めていない。
