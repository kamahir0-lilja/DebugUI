# ADR 0001: Runtime / Editorで共有するページの所有権

Status: Accepted

## 背景

同じ`DebugPage`をゲーム画面とEditorウィンドウで操作したい。
VisualElementは一度に二つの親・パネルへ接続できず、ページをパネル間で移すと
テーマ、フォーカス、テキスト描画の前提が変わる。
初期整備時点の [HostRegistry](../../Packages/com.kamahir0.debug-ui/Runtime/Window/HostRegistry.cs) と
[Editorの知見](../knowledge/ui-toolkit-editor-panels.md)に既存の設計理由がある。

## 判断と理由

ページのデータと表示を共有し、Runtime / Editorのどちらが接続を所有するかを一か所で管理する。
所有権を変えるときは旧ホストの処理を停止・切り離してから新ホストへ渡す。
前の表示先のアニメーションや描画設定が、移動後のページへ適用されないようにする。

二つの表示コピーを同期する方式は、入力・通知・ページ状態の二重管理が増えるため、初期基準では採用しない。
呼び出し箇所ごとの独立したdetach/attachは、実行順序と共有状態を追いにくくする。

## 帰結と境界

ユーザーに見える契約は [DBG-HOST-001](../specs/runtime-and-hosts.md#dbg-host-001) が所有する。
このADRは内部クラス名を永久に固定するものではない。
構造を変える際も、単一の接続先・旧処理の停止・スタイルの持ち越し防止を検証する。
ページ再接続のテストとUI-09の実操作は相互補完であり、テスト成功だけで文字描画の問題がないと推定しない。

初期の仕様駆動環境整備で、既存の選択をAgent Decisionとして明文化した。今回Unityで再検証したという記録ではない。
